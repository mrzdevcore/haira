# Haira AI Rules

> **Purpose**: Strict, enforceable rules for AI agents working on the Haira compiler.
> **Version**: 2.0.0
> **Last Updated**: 2026-02-11

---

## 1. Project Overview

Haira is a **general-purpose agentic orchestration programming language**. Workflows, agents, and tools are first-class citizens — not library imports.

### Identity

**Tagline**: "Build agents and workflows, not boilerplate."

Haira replaces:
- **Python + LangChain/LangGraph** — for code-first agent builders
- **n8n / Make / Zapier** — for workflow automation
- **CrewAI / AutoGen** — for multi-agent systems

All in one compiled, type-safe language with native binaries.

### Tech Stack
- **Language**: Rust 2021 edition
- **Backend**: Cranelift (native code generation)
- **Runtime**: `haira-runtime` (agents, workflows, providers, streaming)
- **File Extension**: `.haira`

### The Four Agentic Primitives

| Keyword | Purpose |
|---------|---------|
| `provider` | LLM backend configuration |
| `tool` | Function with LLM-visible description + auto-schema |
| `agent` | LLM entity with model, system prompt, tools |
| `workflow` | Composable function with trigger, typed I/O |

Everything else reuses existing Haira: `struct`, `fn`, `if`, `for`, `spawn`, `chan`, `match`, `import`, `@` (decorator syntax).

## 2. Compiler Pipeline

The pipeline order is **immutable**. Never reorder these phases:

```
Source (.haira)
       |
       v
   +--------+
   | Lexer  |  --> Tokens
   +--------+
       |
       v
   +--------+
   | Parser |  --> AST (includes provider, tool, agent, workflow nodes)
   +--------+
       |
       v
   +----------+
   | Resolver |  --> Resolved AST (imports, symbols, providers)
   +----------+
       |
       v
   +-------------+
   | Type Checker|  --> Typed AST (tools, agents, workflows validated)
   +-------------+
       |
       v
   +----------+
   | Lowering |  --> HIR (High-level IR)
   +----------+
       |
       v
   +----------+
   | Codegen  |  --> Cranelift IR --> Native binary
   +----------+
```

**Note**: There is NO AI phase in the compiler pipeline. All LLM interaction happens at **runtime** through agents, not at compile time.

## 3. Forbidden Actions

### NEVER Do These

| Action | Status |
|--------|--------|
| Use `unsafe` code anywhere | **FORBIDDEN** — no exceptions |
| Reorder compiler pipeline phases | **FORBIDDEN** — immutable architecture |
| Change crate naming from `haira-*` | **FORBIDDEN** — convention |
| Change file extension from `.haira` | **FORBIDDEN** — language identity |
| Add semicolons to Haira syntax | **FORBIDDEN** — language design |
| Add the `ai` keyword back | **FORBIDDEN** — removed, all LLM via `agent` |
| Create CIR/HIF cache files | **FORBIDDEN** — no compile-time AI |

## 4. Required Actions

### Before Completing ANY Task

AI agents **MUST** run these commands and ensure they pass:

```bash
# 1. Format code
make fmt

# 2. Run linter (must pass with zero warnings)
make lint

# 3. Build the project
make build

# 4. Run all tests
cargo test
```

**Do NOT mark a task as complete if any of these fail.**

### Before Writing New Code

AI agents **MUST**:

1. **Search for existing code first**
   - Use `Grep` to find similar functionality
   - Use `Glob` to find related files
   - Check if a function/type already exists
   - **Prevent dead code and duplication**

2. **Read before editing**
   - Always read a file before modifying it
   - Understand the existing patterns
   - Follow the established conventions

3. **Check crate boundaries**
   - Understand which crate owns the functionality
   - Don't duplicate across crates
   - Respect the pipeline order

## 5. Language Design Decisions

These are **settled decisions**. Do not propose alternatives.

| Decision | Choice |
|----------|--------|
| `ai` keyword | **Removed** — all LLM interaction goes through `agent` |
| Workflow structure | **Function-style** — params are input, return type is output |
| Trigger syntax | **`@decorator`** style — `@webhook("/path")` before workflow |
| Parallel execution | **`spawn { }` block** — reuses existing keyword, returns list |
| Agent output type | **Left-side annotation** — `result: Type, err = agent.run(req)` |
| Provider syntax | **`provider` keyword** — top-level config block |
| Tool description | **Triple-quote inside body** — `"""..."""` enforced by compiler |
| Streaming | **`stream<T>`** type — iterable with `for`, used by `.stream()` and `@websocket` |
| Agent memory | **Built-in** — `conversation(max_turns)`, `summary(max_tokens)`, `none` |
| Sessions | **Named parameter** — `session: "id"` on `.ask()`, `.run()`, `.stream()` |

## 6. Code Standards

### Rust Conventions

| Element | Convention | Example |
|---------|------------|---------|
| Crate names | `haira-*` (hyphenated) | `haira-lexer` |
| Module names | `snake_case` | `token_stream` |
| Function names | `snake_case` | `parse_expression` |
| Type/Struct names | `PascalCase` | `TokenKind` |
| Constants | `SCREAMING_SNAKE_CASE` | `MAX_RECURSION_DEPTH` |

### Visibility Rules

```rust
// PREFER: Internal by default
pub(crate) fn internal_helper() { }

// ONLY for intentional public API
pub fn public_api_function() { }

// Private for implementation details
fn private_impl() { }
```

### Error Handling

All crates **MUST** use:

```rust
// Error definitions with thiserror
use thiserror::Error;

#[derive(Error, Debug)]
pub enum MyError {
    #[error("descriptive message: {0}")]
    Variant(String),
}

// Error display with miette (for user-facing errors)
use miette::Diagnostic;

#[derive(Error, Diagnostic, Debug)]
#[error("user-friendly message")]
#[diagnostic(code(haira::error_code))]
pub struct UserFacingError {
    #[source_code]
    src: String,
    #[label("this is wrong")]
    span: SourceSpan,
}
```

### Span Tracking

**Every** AST, HIR, and MIR node **MUST** carry a `Span`:

```rust
pub struct Expr {
    pub kind: ExprKind,
    pub span: Span,  // Required for error reporting
}
```

## 7. Dead Code Policy

- **Remove dead code immediately** — no deprecation period
- **Remove unused imports** — clippy will catch these
- **Remove unused functions** — if not called, delete
- **Remove commented-out code** — version control exists

## 12. Common Tasks

### Adding a New AST Node

1. Define in `haira-ast/src/ast.rs`
2. Add span field
3. Update parser in `haira-parser`
4. Update any visitors/walkers
5. Run `make dev`

### Adding a New Agentic Construct

1. Define AST node with span
2. Add lexer token (if new keyword)
3. Implement parser rule
4. Add resolver validation
5. Add type checking rules
6. Lower to HIR (runtime calls)
7. Run full test suite
