# Haira AI Rules

> **Purpose**: Strict, enforceable rules for AI agents working on the Haira compiler.
> **Version**: 3.0.0
> **Last Updated**: 2026-02-15

---

## 1. Project Overview

Haira is a **general-purpose agentic orchestration programming language**. Workflows, agents, and tools are first-class citizens — not library imports.

### Identity

**Tagline**: "Build agents and workflows, not boilerplate."

Haira replaces:
- **Python + LangChain/LangGraph** — for code-first agent builders
- **n8n / Make / Zapier** — for workflow automation
- **CrewAI / AutoGen** — for multi-agent systems

All in one compiled, type-safe language with native binaries.

### Tech Stack

- **Compiler**: Go 1.22
- **Codegen**: Haira source → Go source → `go build` → native binary
- **Runtime**: Embedded in compiler via `go:embed` (`compiler/internal/runtime/embedded/haira/`)
- **File Extension**: `.haira`

### Agentic Primitives

Current language-level primitives for agentic orchestration:

| Keyword | Purpose |
|---------|---------|
| `provider` | LLM backend configuration (API keys, model, endpoint) |
| `tool` | Function with LLM-visible description + auto-schema |
| `agent` | LLM entity with model, system prompt, tools, memory |
| `workflow` | Composable function with trigger, typed I/O |

These are not a closed set — the language may grow new agentic capabilities (e.g., embeddings, tool packs, knowledge bases) as needed.

Everything else reuses core Haira: `fn`, `struct`, `enum`, `if`, `for`, `while`, `match`, `spawn`, `defer`, `import`, `@` (decorator syntax).

## 2. Compiler Pipeline

The pipeline order is **immutable**. Never reorder these phases:

```
Source (.haira)
       |
       v
   +--------+
   | Lexer  |  --> Tokens
   +--------+
       |
       v
   +--------+
   | Parser |  --> AST
   +--------+
       |
       v
   +---------+
   | Checker |  --> Type-checked AST + diagnostics
   +---------+
       |
       v
   +---------+
   | Codegen |  --> Generated Go source
   +---------+
       |
       v
   +----------+
   | go build |  --> Native binary
   +----------+
```

**Note**: There is NO AI phase in the compiler pipeline. All LLM interaction happens at **runtime** through agents, not at compile time.

### Codegen Architecture

The Go code generator uses an **8-pass emission order**:

1. Providers → `var` declarations
2. Tools → functions + `ToolDef` vars
3. Agents → `var` + init functions (topologically sorted for handoffs)
4. Workflows → handler functions + `WorkflowDef` vars
5. Top-level variables
6. Type definitions + Enums
7. Methods
8. Regular functions + `main()`

Key details:
- Agent init calls are **topologically sorted** (handoff targets initialized first)
- Streaming workflows generate both `StreamHandler` (SSE) and `Handler` (JSON fallback)
- Import detection is **multi-pass** (fmt, encoding/json, sync, haira runtime)

## 3. Forbidden Actions

### NEVER Do These

| Action | Status |
|--------|--------|
| Reorder compiler pipeline phases | **FORBIDDEN** — immutable architecture |
| Change file extension from `.haira` | **FORBIDDEN** — language identity |
| Add semicolons to Haira syntax | **FORBIDDEN** — language design |
| Add the `ai` keyword back | **FORBIDDEN** — removed, all LLM via `agent` |
| Add external dependencies to the compiler | **FORBIDDEN** — compiler stays dependency-free |
| Break the 8-pass codegen emission order | **FORBIDDEN** — ordering guarantees correctness |

### Before Writing New Code

AI agents **MUST**:

1. **Search for existing code first**
   - Use `Grep` to find similar functionality
   - Use `Glob` to find related files
   - Check if a function/type already exists
   - **Prevent dead code and duplication**

2. **Read before editing**
   - Always read a file before modifying it
   - Understand the existing patterns
   - Follow the established conventions

3. **Check package boundaries**
   - Understand which package owns the functionality
   - Don't duplicate across packages
   - Respect the pipeline order

## 5. Language Design Decisions

These are **settled decisions**. Do not propose alternatives.

| Decision | Choice |
|----------|--------|
| `ai` keyword | **Removed** — all LLM interaction goes through `agent` |
| Workflow structure | **Function-style** — params are input, return type is output |
| Trigger syntax | **`@decorator`** style — `@webhook("/path")` before workflow |
| Parallel execution | **`spawn { }` block** — returns list of results |
| Agent output type | **Left-side annotation** — `result: Type, err = agent.run(req)` |
| Provider syntax | **`provider` keyword** — top-level config block |
| Tool description | **Triple-quote inside body** — `"""..."""` mandatory |
| Streaming | **`-> stream`** return type with `agent.stream()`, served as SSE |
| Agent memory | **Built-in** — `conversation(max_turns)`, `summary(max_tokens)`, `none` |
| Sessions | **Named parameter** — `session: "id"` on `.ask()`, `.run()`, `.stream()` |
| Agent handoffs | **`handoffs: [AgentA, AgentB]`** field on agent |
| String interpolation | **`${expr}`** syntax |
| Error propagation | **`?` operator** — unwraps `(T, error)` tuples (codegen WIP) |
| Pipe operator | **`value | fn1 | fn2`** — left-associative function chaining |

## 6. Code Standards

### Go Conventions

| Element | Convention | Example |
|---------|------------|---------|
| Package names | `lowercase` | `codegen`, `parser` |
| Exported functions | `PascalCase` | `ExprToGo`, `Compile` |
| Unexported functions | `camelCase` | `parseExpr`, `emitStmt` |
| Types/Structs | `PascalCase` | `TokenKind`, `Diagnostic` |
| Constants | `PascalCase` or groups | `Error`, `Warning` |
| File names | `snake_case.go` | `expressions.go`, `agentic.go` |

### Error Handling

The compiler uses `internal/errors` for diagnostics:

```go
// Creating a diagnostic
errors.Diagnostic{
    Level:   errors.Error,
    Message: "type mismatch",
    Span:    node.Span,
    File:    filename,
    Hint:    "expected int, got string",
}

// Rendering with source context
errors.PrettyPrint(diag, source)
// Output:
//   main.haira:5:12: error: type mismatch
//     |
//   5 |     return "hello" + 42
//     |            ^^^^^^^^^^^^^^ expected int, got string
```

### Span Tracking

**Every** AST node **MUST** carry a `Span`:

```go
type Expr struct {
    Node ExprNode
    Span Span     // Required for error reporting
}
```

- **Remove dead code immediately** — no deprecation period
- **Remove unused imports** — `go vet` will catch these
- **Remove unused functions** — if not called, delete
- **Remove commented-out code** — version control exists

## 12. Common Tasks

### Adding a New AST Node

1. Define the node struct in `internal/ast/ast.go`
2. Add the `exprKind()` or `stmtKind()` marker method
3. Add a new token in `internal/token/token.go` (if new keyword)
4. Update the lexer in `internal/lexer/` (if new keyword)
5. Implement the parser rule in `internal/parser/`
6. Add type checking in `internal/checker/`
7. Add Go codegen in `internal/codegen/`
8. Run `make dev`

### Adding a New Standard Library Module

1. Create the runtime implementation in `compiler/internal/runtime/embedded/haira/<module>.go.src`
2. Add codegen support in `internal/codegen/stdlib.go` (`resolveQualified()` + `IsStdlibImport()`)
3. Add return type in `internal/codegen/expressions.go` (`orelseReturnType()`) if constructors return structs
4. Add an example in `examples/`
5. Run `make dev && make build-examples`

### Adding a New Agentic Feature

1. Define AST node with Span
2. Add token (if new keyword)
3. Update lexer and parser
4. Add checker validation
5. Add codegen in `internal/codegen/agentic.go`
6. Add runtime support in `compiler/internal/runtime/embedded/haira/`
7. Run full test suite: `make ci`

## 14. Quick Reference

### Must Do
- Search existing code before writing new code
- Run `make dev` before completing any task
- Use `errors.Diagnostic` for compiler messages
- Include `Span` on every AST node
- Follow Go naming conventions (exported = PascalCase)
- Remove dead code immediately

### Must Not
- Reorder compiler pipeline
- Add `ai` keyword back
- Add semicolons to Haira syntax
- Add external dependencies to the compiler
- Break the 8-pass codegen order

### CLI Commands
```bash
haira build <file> [-o output]   # Compile to native binary
haira run <file>                 # Compile and run
haira check <file>               # Type-check only
haira parse <file>               # Show AST
haira lex <file>                 # Show tokens
haira emit <file>                # Show generated Go code
haira lsp                        # Start language server
```
